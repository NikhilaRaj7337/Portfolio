A grounded document Q&A assistant, with the evaluation to back it

A retrieval-augmented assistant that answers only from retrieved sources, remembers the conversation, and comes with a harness that scores relevance, retrieval precision and unsupported claims on a labeled test set.

The problem

Most RAG demos show a few good answers and stop there. I wanted an assistant that refuses to answer beyond its sources, and a repeatable way to tell whether a change to chunking, embeddings or prompts actually made it better.

Architecture

Ingest.txt / .md documents
→
Chunk + embed3 strategies, cached by content hash
→
FAISS retrievetop-k chunks
→
Grounded answerwith chat memory and sources
  • Ingestion splits documents, embeds the chunks and persists a FAISS index. Embeddings are cached on disk by content hash and sent in batches, so re-ingesting unchanged text costs no API calls.
  • The chain combines the retriever, buffered conversation memory and a prompt that tells the model to answer only from retrieved context and say "I don't know" otherwise.
  • One provider setting switches both the chat model and the embedding model between Gemini and OpenAI with no code changes.

Chunking strategies

StrategyHow it splits
recursiveBy characters with overlap, respecting paragraph and sentence boundaries first
tokenBy token count with tiktoken, for tight context budgets
semanticGroups sentences until embedding similarity drifts past a threshold

How it's evaluated

A labeled test set of questions, reference answers and gold source documents runs through the chain. Three metrics are averaged across it:

  • Answer relevance: cosine similarity between the generated answer's embedding and the reference answer's.
  • Retrieval precision@k: whether the gold source appears among the top-k retrieved chunks.
  • Hallucination rate: an LLM grader splits the answer into individual claims and reports the share not supported by the retrieved context.

Results

Relevance0.84mean cosine similarity to references
Precision@41.00gold source in the top 4 chunks
Hallucination0%unsupported claims, LLM-graded
Scope of these numbers. They come from a 4-question labeled set over a 2-document corpus, using gemini-3.5-flash-lite. With only two source files, perfect precision@4 shows the pipeline works, not that retrieval holds up at scale. The hallucination grade comes from an LLM, not human review.

Next steps

  • Grow the corpus and test set, with distractor documents, so retrieval precision means something.
  • Add hybrid BM25 + dense retrieval fused with Reciprocal Rank Fusion, for queries with exact identifiers.
  • Compare the three chunking strategies head to head on the larger set.
  • Add RAGAS for standardized faithfulness and context metrics, and a FastAPI backend with a small web front end.
